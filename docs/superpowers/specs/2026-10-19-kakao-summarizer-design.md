# 카톡 채팅방 요약 에이전트 — 설계

- 날짜: 2026-10-19
- 상태: 승인 대기

## 1. 목적

Claude Code에서 "카톡 OO방 요약해줘"라고 요청하면, Mac 카카오톡 앱에서 해당 채팅방의
최근 대화를 자동으로 읽어 요약을 돌려준다. 대화 내보내기 같은 수동 단계는 없다.

### 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 입력 방식 | macOS 접근성(Accessibility) API로 실행 중인 카톡 Mac 앱의 화면 텍스트를 읽음 |
| 실행 시점 | 사용자 요청 시 (on-demand). 정기 자동 실행은 범위 밖 |
| 기본 범위 | 안 읽은 메시지 전부. 안 읽은 게 없으면 최근 24시간. 요청에 범위가 명시되면 그걸 따름 |
| 형태 | Claude Code 서브에이전트 + Swift CLI 헬퍼 |

### 범위 밖 (YAGNI)

- 정기 실행, 알림 전송
- 여러 방 일괄 요약
- 메시지 입력/전송 등 읽기 외의 조작
- 로컬 DB 복호화, 화면 캡처 OCR
- 원문 대화 저장/캐시

### 사전 검증 결과 (spike, 2026-10-19)

- 채팅 목록 창: 방 이름, 안 읽은 수, 마지막 시각, 미리보기, 오픈채팅 배지가 AX 트리에 텍스트로 노출됨.
- 채팅방 창: 메시지 한 줄 = `AXRow` 하나. 본문, 발신자, 시각, 날짜가 노출됨 (세부는 §4).
- 창에 로드된 행은 약 50개뿐 → 더 과거는 스크롤로 불러와야 함 (미검증, §7).
- 채팅방을 열면 카톡이 해당 방을 읽음 처리함.

## 2. 구성 요소

```
~/kakao-summarizer/                    Swift Package (git 관리)
  Sources/kakao-read/                  CLI: 카톡 화면 읽기 전용
  Tests/KakaoReadCoreTests/            swift-testing (CLT 환경이라 XCTest 없음)
  agent/kakao-summarizer.md            서브에이전트 정의 원본 (install.sh가 복사)
~/.claude/agents/kakao-summarizer.md   서브에이전트 정의
```

`scripts/install.sh`가 `kakao-read`를 `~/.local/bin/kakao-read`에, 에이전트 정의를 `~/.claude/agents/`에 설치한다.

### 2.1 `kakao-read` 명령

| 명령 | 동작 | 카톡에 가하는 조작 |
|---|---|---|
| `kakao-read list` | 채팅 목록을 JSON 배열로 출력: `name`, `unread`, `lastTime`, `isOpenChat`, `isMe`(나와의 채팅 = 사용자 본인 이름) | 없음 |
| `kakao-read messages --room <이름> (--count N \| --since <기간>)` | 방의 메시지를 JSON Lines로 출력 | 방 열기(필요 시), 스크롤 |
| `kakao-read dump [--window <제목>]` | 원시 AX 트리 출력 (디버그·fixture 작성용, 도움말에 노출 안 함) | 없음 |

`--since`는 `24h`, `90m`, `2d` 형식, 또는 `today`(오늘 00:00부터)를 받는다.

### 2.2 안전 원칙

`kakao-read`가 카톡에 하는 조작은 **방 열기와 스크롤 두 가지뿐**이다.
키 입력·텍스트 설정·전송 관련 코드는 작성하지 않는다. 카톡이 꺼져 있어도 자동 실행하지 않는다.

## 3. 동작 흐름

에이전트가 "등산 수다방 요약해줘"를 받았을 때:

1. `kakao-read list` 실행.
2. 방 이름 매칭: 정확히 일치 → 부분 일치(대소문자·공백·이모지 무시) 순.
   대상은 목록의 방과 이미 열려 있는 채팅방 창(조용한 채팅방 폴더처럼 목록에 안 보이는 방 포함)의 합집합.
   후보가 0개거나 2개 이상이면 요약하지 않고 후보를 보여주며 되묻는다.
3. 매칭된 방의 `unread`를 기록한다. **방을 열기 전에 읽어야 한다** (열면 0이 됨).
4. 범위 결정:
   - 요청에 범위가 있으면 그것 ("오늘" → `--since today`, "최근 100개" → `--count 100`)
   - 아니면 `unread > 0` → `--count <unread>`
   - 아니면 `--since 24h`
5. `kakao-read messages ...` 실행.
   - 해당 방 창이 이미 열려 있으면 그 창 사용.
   - 아니면 목록에서 해당 행에 AX 액션으로 열기.
6. 출력을 읽고 §5 형식으로 요약해 반환한다.

## 4. 메시지 파싱 규칙

### 4.1 AXRow에서 읽는 요소

| 요소 | 의미 |
|---|---|
| `AXTextArea`의 값 | 본문 |
| `AXHelp`가 있는 `AXStaticText` | 메타. `AXHelp` = 날짜 (`2026. 10. 19.`), 값 = `[안읽은수][⏎시각]` (`44⏎오전 11:51`, `44`, 또는 시각만) |
| `프로필` 버튼(`AXDescription=프로필`) + 메타가 아닌 `AXStaticText` | 새 발신자 시작. 그 텍스트가 발신자 이름 |

안 읽은 사람 수는 버린다.

### 4.2 보정 규칙

- **발신자 이어 붙이기**: 프로필이 없는 행은 바로 위 행의 발신자를 상속.
- **시각 채우기**: 시각은 같은 분 묶음의 마지막 행에만 표시된다. 행을 역순으로 훑으며 비어 있는 시각을 바로 아래 행의 시각으로 채운다. 끝까지 없으면 `null`.
- **내 메시지**: 본문 요소의 가로 중심이 창 가로 중심보다 오른쪽이면 `sender: "나"`. 이 판별은 상속 규칙보다 우선한다.
- **비텍스트 메시지**: 메타가 있는데 본문이 없거나 본문이 첨부 표식(U+FFFC)뿐인 행 → `text: "[사진/이모티콘]"`, `kind: "media"`. `badge`로 시작하지 않는 이미지 description이 있으면 `[사진/이모티콘: <설명>]`.
- **시스템 행**: 프로필도 메타도 없고 텍스트만 있는 행(입장/퇴장/날짜 구분선) → `sender: "system"`, `kind: "system"`.
- **빈 행**: 텍스트·이미지 모두 없는 행은 버린다.

### 4.3 출력 형식 (JSON Lines, 오래된 것 → 최신 순)

```json
{"date":"2026-10-19","time":"11:51","sender":"철수/90/서울","kind":"text","text":"이번 주 토요일 어때요"}
{"date":"2026-10-19","time":"11:51","sender":"나","kind":"text","text":"좋아요 저도 갈게요"}
```

`kind` ∈ `text | media | system`. 시각은 24시간제 `HH:mm`.

### 4.4 스크롤 수집과 중복 제거

0. 스크롤을 맨 아래로 내린다 (방이 "여기까지 읽었습니다" 위치로 열릴 수 있음).
1. 현재 보이는 행을 파싱해 배치 B₀를 얻는다.
2. 세로 스크롤바 값을 줄여(위로) 스크롤 → 짧게 대기 → 새 배치 Bₖ.
3. 누적 결과 R의 앞부분과 Bₖ의 뒷부분이 겹치는 가장 긴 구간을 `(date, kind, text)` 시퀀스 비교로 찾고(system 행은 date 제외; 발신자·시각은 창 가장자리에서 비어 있을 수 있어 비교에서 뺌, 병합 시 서로 보충), 겹치지 않는 앞부분만 R 앞에 붙인다.
   개별 메시지가 아닌 연속 시퀀스로 비교하므로 "ㅋㅋㅋ" 같은 반복 메시지를 잘못 지우지 않는다.
   카톡 스냅샷은 불러온 행 전체이고, 수집 중 새 메시지 도착이나 사진·이모티콘 행 렌더링으로 중간 행이 스냅샷마다 빠졌다 나타난다. 그래서 겹침 전체가 일치할 필요는 없다: 가장 긴 일치 구간을 기준으로 잡고 양옆에서 다시 일치 구간을 찾으며(difflib 방식), 일치하지 않는 행은 양쪽 모두 남긴다.
   겹침이 0이면 스크롤 간격이 너무 컸던 것으로 보고 원위치로 되돌린 뒤 간격을 절반으로 줄여 재시도한다. 간격이 0.005 미만이 되면 부분 수집으로 끝낸다(`스크롤 병합 실패`).
   새 행이 없는 스크롤이 3번 연속이면 대화 맨 위로 본다. `--since`에서 맨 위 도달은 전체 범위를 다 읽은 것이므로 부분 수집이 아니다.
4. 종료 조건 (먼저 만족하는 것):
   - `--count N`: R의 `kind != system` 메시지가 N개 이상 → 최신 N개만 출력
   - `--since T`: R의 가장 오래된 메시지가 T보다 이전 → T 이후만 출력
   - 스크롤해도 새 행이 없음 (대화 맨 위)
   - 스크롤 50회 도달
5. 범위를 다 못 채우고 끝났으면 stderr에 경고 한 줄: `WARN partial: 68개 요청, 50개 수집 (대화 맨 위 도달)`.

## 5. 요약 형식과 에이전트

### 5.1 요약 형식 (한국어)

```
### <방 이름>
<범위 설명> · <첫 시각>–<끝 시각> · 참여 N명

**한 줄 요약:** …

**주요 화제**
- 화제: 요지 (주요 발언자)

**약속·일정·결정**        ← 없으면 섹션 생략
- …

**나에게 온 질문/언급**    ← 없으면 생략
- 발신자: "인용" ← 답장 필요해 보임

**공유된 링크**            ← 없으면 생략
- 설명 — URL
```

규칙:
- 길이는 메시지 수에 비례: 30개 이하면 3~5줄, 수백 개면 화제 최대 7개.
- 잡담은 묶어서 압축. 약속·일정·결정·질문은 누락하지 않는 것을 우선.
- 원문에 없는 내용은 추측하지 않는다. 애매하면 "~로 보임".
- `WARN partial`이 있었으면 범위 설명에 반영 ("안 읽은 68개 중 50개만 읽음 (대화 맨 위 도달)").
- "나에게 온 질문/언급"은 발신자가 "나"가 아닌 메시지 중 질문형이거나 사용자 이름이 언급된 것.

### 5.2 에이전트 정의 (`~/.claude/agents/kakao-summarizer.md`)

- `description`: 카톡/카카오톡 + 요약/정리 요청 시 사용한다는 내용을 담아 자동 위임되게 한다.
- `tools: Bash` — 지시문에서 `kakao-read` 실행만 허용.
- `model: sonnet`
- 원문을 파일로 저장하지 않는다. stdout을 바로 읽고 요약만 반환한다.
- `kakao-read` 오류는 §6의 안내 문구를 그대로 사용자에게 전달한다.

## 6. 오류 처리

| 상황 | 종료 코드 | stderr 안내 |
|---|---|---|
| 정상 (부분 수집 포함) | 0 | 부분 수집 시 `WARN partial: …` |
| 일반 오류 / 잘못된 인자 | 1 | 사용법 |
| 접근성 권한 없음 | 2 | 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 터미널 앱 허용 후 재시작 |
| 카톡 미실행 | 3 | 카카오톡을 실행해 주세요 |
| 목록 창 없음 (잠금/로그인 화면) | 4 | 카카오톡 잠금을 풀거나 로그인해 주세요 |
| 메인 창이 채팅 탭이 아님 (친구/더보기 탭) | 4 | 메인 창에서 채팅 탭(⌘2)을 선택해 주세요 |
| 채팅방 열기 실패 | 1 | 카톡에서 직접 열어 둔 뒤 다시 시도해 주세요 |
| 방 없음 / 후보 여러 개 | 5 | stdout에 후보 JSON 배열 (`list`와 같은 형식) |
| 행은 있는데 파싱된 메시지 0개 | 6 | 카톡 UI 구조가 바뀐 것 같음, `kakao-read dump` 결과 확인 필요 |

## 7. 구현 순서상 먼저 확인할 미검증 가정

구현 첫 단계에서 실제 카톡으로 확인하고, 하나라도 실패하면 진행을 멈추고 사용자에게 보고한다.

1. 목록 행에 AX 액션(`AXPress`/`AXOpen` 등)으로 채팅방 창을 열 수 있다.
2. 채팅방 세로 스크롤바의 `AXValue`를 바꾸면 과거 메시지가 로드된다.
3. 내 메시지와 상대 메시지를 본문 요소의 가로 위치로 구분할 수 있다.

## 8. 코드 구조와 테스트

### 8.1 계층

```
AXReader   카톡 AX 트리 → AXNode 스냅샷
           AXNode = { role, value, help, description, frame, children }  (순수 값 타입)
Parser     (AXNode 행 목록, 창 frame) → [Message]           순수 함수
Collector  스크롤·스냅샷 함수를 주입받아 반복·병합·종료 판단
CLI        인자 파싱, JSON 출력, 종료 코드
```

### 8.2 테스트

- **단위 테스트 (swift-testing)**
  - Parser: 발신자 상속, 시각 역방향 채우기, 내 메시지 판별, media/system 행, 빈 행, 날짜 파싱, 오전/오후 → 24시간제.
  - Collector: 겹침 병합, 동일 텍스트 반복, 겹침 0 시 간격 축소, `--count`/`--since` 종료, 맨 위 도달, 50회 상한, 부분 수집 경고.
  - 방 이름 매칭: 정확/부분/이모지 무시/0개/다수.
- **Fixture**: 실제 덤프와 같은 구조로 만들되 이름·본문은 가짜. 실제 대화 내용은 저장소에 커밋하지 않는다.
- **실제 동작 확인 (수동)**: 실제 방 하나로 `list` → `messages --count 30` → 에이전트 요약을 실행해 화면과 대조.
